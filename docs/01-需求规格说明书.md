## 1. 项目概述

### 1.1 项目背景

贷后管理是信贷业务的核心环节。传统贷后管理依赖人工分析借款人还款行为、财务状况、风险信号等数据，效率低、覆盖面有限、风险识别滞后。本项目旨在构建一个**贷后智能体（Post-Loan Agent）**，自动接收并分析源头系统加工后的数据，生成结构化的贷后分析报告，辅助风险管理人员决策。

### 1.2 项目目标

| 目标 | 描述 |
|------|------|
| 自动化分析 | 自动解析源头加工数据，识别贷后风险信号 |
| 智能评级 | 基于多维度指标对借款人进行风险评级（A/B/C/D/E） |
| 报告生成 | 自动生成结构化贷后分析报告，支持 PDF/HTML 导出 |
| 预警推送 | 对高风险借款人触发预警，推送至相关人员 |
| 可追溯 | 全流程留痕，支持报告回溯与审计 |

### 1.3 系统边界

```
┌─────────────┐     ┌───────────────────┐     ┌──────────────┐
│  源头系统    │ ──> │  贷后智能体        │ ──> │  报告/预警    │
│ (数据加工)   │     │  (本项目)          │     │  (输出)       │
└─────────────┘     └───────────────────┘     └──────────────┘
```

- **上游**：源头加工系统，提供标准化的贷后数据（JSON/API 推送）
- **下游**：报告存储系统、预警通知系统（飞书/邮件/短信）

## 2. 功能需求

### 2.1 数据接入模块

| 需求编号 | 需求名称 | 描述 | 优先级 |
|---------|---------|------|--------|
| FR-001 | API 数据接入 | 提供 REST API 接口，接收源头系统推送的贷后数据 | P0 |
| FR-002 | 数据格式校验 | 对接入数据进行字段级校验，不合规数据拒绝并返回错误信息 | P0 |
| FR-003 | 数据去重 | 按借款人 ID + 报告期次去重，避免重复分析 | P1 |
| FR-004 | 批量导入 | 支持通过文件（CSV/Excel）批量导入贷后数据 | P2 |

### 2.2 风险分析模块

| 需求编号 | 需求名称 | 描述 | 优先级 |
|---------|---------|------|--------|
| FR-010 | 还款行为分析 | 分析借款人还款准时率、逾期次数、逾期天数趋势 | P0 |
| FR-011 | 财务状况分析 | 分析借款人收入变化、负债率变化、现金流状况 | P0 |
| FR-012 | 风险信号识别 | 识别多头借贷、担保链异常、诉讼记录等风险信号 | P0 |
| FR-013 | 信用评分计算 | 基于多维指标加权计算借款人风险评分（0-100） | P0 |
| FR-014 | 风险评级映射 | 评分映射为 A/B/C/D/E 五级评级 | P0 |
| FR-015 | 趋势分析 | 对比历史数据，识别风险上升趋势 | P1 |

### 2.3 报告生成模块

| 需求编号 | 需求名称 | 描述 | 优先级 |
|---------|---------|------|--------|
| FR-020 | 报告模板管理 | 维护贷后分析报告模板，支持模板版本管理 | P1 |
| FR-021 | 自动生成报告 | 根据分析结果自动生成结构化报告 | P0 |
| FR-022 | 报告内容 | 包含：借款人概况、还款分析、财务分析、风险信号、评级结论、建议措施 | P0 |
| FR-023 | 报告导出 | 支持导出为 PDF 和 HTML 格式 | P1 |
| FR-024 | 报告查询 | 支持按借款人/日期/评级查询历史报告 | P0 |

### 2.4 预警管理模块

| 需求编号 | 需求名称 | 描述 | 优先级 |
|---------|---------|------|--------|
| FR-030 | 预警规则配置 | 配置预警触发条件（如评级降至 D/E、逾期超过阈值） | P1 |
| FR-031 | 自动预警 | 分析结果触发预警规则时自动生成预警工单 | P0 |
| FR-032 | 预警推送 | 通过飞书消息/邮件推送预警通知给指定人员 | P1 |
| FR-033 | 预警处置 | 预警工单支持接单、处置、关闭流程 | P2 |

### 2.5 智能体编排模块

| 需求编号 | 需求名称 | 描述 | 优先级 |
|---------|---------|------|--------|
| FR-040 | 分析流程编排 | 智能体按步骤编排：数据校验 → 风险分析 → 评级 → 报告生成 → 预警 | P0 |
| FR-041 | 异常自动处理 | 分析过程中遇到异常数据自动降级处理或标记人工介入 | P1 |
| FR-042 | 执行日志 | 记录智能体每一步执行状态，支持全链路追踪 | P0 |

## 3. 输入数据规范

### 3.1 源头数据结构

源头系统推送的标准化 JSON 数据结构如下：

```json
{
  "borrowerId": "BR20260001",
  "borrowerName": "张三",
  "loanId": "LN20260001",
  "reportPeriod": "2026-09",
  "loanInfo": {
    "loanAmount": 500000,
    "loanBalance": 320000,
    "loanType": "经营贷",
    "loanStartDate": "2026-01-15",
    "loanEndDate": "2027-01-14",
    "interestRate": 5.85
  },
  "repaymentInfo": {
    "totalTerms": 12,
    "completedTerms": 8,
    "ontimeCount": 7,
    "overdueCount": 1,
    "maxOverdueDays": 5,
    "currentOverdueDays": 0
  },
  "financialInfo": {
    "monthlyIncome": 35000,
    "monthlyIncomeChange": -0.08,
    "debtRatio": 0.42,
    "debtRatioChange": 0.05,
    "cashFlowStatus": "正常"
  },
  "riskSignals": {
    "multiLending": false,
    "guaranteeChainAbnormal": false,
    "litigationRecord": false,
    "businessAbnormal": false,
    "assetTransfer": false
  },
  "externalData": {
    "creditScore": 680,
    "creditScoreChange": -15,
    "courtFilingCount": 0,
    "taxArrears": false
  }
}
```

### 3.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| borrowerId | String | 是 | 借款人唯一标识 |
| borrowerName | String | 是 | 借款人姓名 |
| loanId | String | 是 | 贷款合同编号 |
| reportPeriod | String | 是 | 报告期次（yyyy-MM） |
| loanInfo.* | Object | 是 | 贷款基本信息 |
| repaymentInfo.* | Object | 是 | 还款行为信息 |
| financialInfo.* | Object | 是 | 财务状况信息 |
| riskSignals.* | Object | 是 | 风险信号信息 |
| externalData.* | Object | 否 | 外部数据信息 |

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|------|------|------|
| NFR-001 | 响应时间 | 单次分析请求 < 3 秒 |
| NFR-002 | 并发能力 | 支持 50 并发分析请求 |
| NFR-003 | 可用性 | 系统可用率 >= 99.5% |
| NFR-004 | 数据安全 | 敏感数据加密存储，接口鉴权访问 |
| NFR-005 | 可扩展性 | 分析规则可配置化，无需改代码即可调整 |
| NFR-006 | 审计日志 | 全操作留痕，日志保留 6 个月 |

## 5. 用户角色

| 角色 | 权限 |
|------|------|
| 风险管理员 | 查看/导出报告、处置预警 |
| 风险审批人 | 审批预警处置结果、查看全部报告 |
| 系统管理员 | 配置规则模板、管理用户权限 |
| 接口调用方 | 通过 API 推送数据、获取分析结果 |
